# 發布前安全檢查清單

此專案目前是學習與展示原型，不是醫療器材。只有在以下項目都有負責人、證據與版本紀錄後，才適合提供給非開發者測試；不得宣稱能診斷、開藥、決定劑量或完整檢查交互作用。

## 每次發布都必須通過

- [ ] `flutter analyze` 無錯誤
- [ ] `flutter test` 全部通過
- [ ] Android debug/release build 成功，並在至少一台實機完成啟動、搜尋、拍照、相簿、入庫、服藥紀錄與重啟後資料保留測試
- [ ] iOS build 成功，並在至少一台實機完成同樣流程
- [ ] 驗證過期與缺少效期的批次無法加入服藥紀錄
- [ ] 驗證同藥名、不同效期保持為不同庫存批次
- [ ] 驗證低庫存、30 天內到期與已過期提示
- [ ] 驗證拒絕相機／相簿權限時 App 不會崩潰且有可理解的訊息
- [ ] 使用真實中文及日文藥盒，各測至少 20 張不同光線／角度照片，記錄正確藥品是否出現在前 3 筆
- [ ] 關閉網路後重新安裝並驗證中／日文 OCR，確認辨識模型確實隨 App 提供
- [ ] 備份測試資料後，驗證升級版本不會遺失庫存與服藥紀錄
- [ ] 匯出 JSON 備份、清除測試資料後重新匯入，核對庫存與服藥紀錄一致，且備份不含照片或 `image_path`
- [ ] 掃描 EAN／UPC／Data Matrix／QR code，確認無符合條碼時不會猜測藥名或自動開啟網址
- [ ] 編輯庫存數量與效期後重啟 App，確認資料仍正確

## 資料與醫療安全門檻

- [ ] 每筆真實藥品資料都有來源 URL、版本日期、授權與 attribution
- [ ] 顯示資料的內容與更新週期經合格藥師或相關專業人員審查
- [ ] 明確說明症狀搜尋只是文字比對，不是個人化建議
- [ ] 不把目前的有效成分文字重複比對宣稱為完整交互作用檢查
- [ ] 效期、劑量與服用紀錄都要求使用者再次核對實體包裝或醫囑
- [ ] 建立錯誤回報與資料更正流程

## 隱私與法遵

- [x] 建立 `PRIVACY.md`，列出照片、庫存、服藥紀錄、掃描與備份的處理方式
- [ ] 發布可由商店頁面存取的正式隱私權政策網址
- [ ] 確認 OCR 全程在裝置端；若未來加入雲端服務，必須先取得同意並更新政策
- [ ] 不在 log、crash report 或 analytics 傳送藥名、照片、服藥紀錄等敏感資料
- [ ] 完成目標市場的醫療器材、健康資料與消費者保護法規評估
- [ ] 選定並加入程式碼 `LICENSE`

## 發布工程

- [ ] 將 Android application ID 與 iOS bundle identifier 改為正式且唯一的識別碼
- [ ] 建立受保護的 Android/iOS 簽章與金鑰備份流程，不把密鑰提交到 Git
- [ ] 設定版本號、release notes、支援聯絡方式與最低系統版本
- [ ] 將 Flutter 平台骨架與 `pubspec.lock` 納入版本控制，確保乾淨 clone 可以重現建置
- [ ] 在 CI 增加至少一個 Android build job，正式發行則增加簽章後產物驗證
- [ ] 完成無障礙、字體放大、小螢幕、深色模式與中／日文實機檢查

## 目前不能宣稱的能力

- AI 問診或診斷
- 完整藥物交互作用判定
- 自動決定安全劑量或服藥時機
- 保證 OCR、藥品辨識或資料庫內容正確
- 可取代醫師、藥師或實體藥品包裝
